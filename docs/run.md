**Linux 设备驱动模型是一套统一管理设备、驱动及其关系的机制。** 核心有三个对象：

| 对象 | 数据结构 | 作用 |
|---|---|---|
| **设备** | `struct device` | 表示一个具体设备实例，记录其归属和状态 |
| **驱动** | `struct device_driver` | 描述能支持哪些设备，以及操作它们的回调 |
| **总线** | `struct bus_type` | 组织设备和驱动，提供匹配规则 |

基本流程是：

**发现或描述设备 → 注册设备和驱动 → 总线匹配 → 调用 `probe()` → 成功绑定并提供功能。**

设备和驱动谁先注册都可以；匹配成功后，`probe()` 为该设备准备资源、初始化硬件。设备移除或驱动解绑时，通常通过 `remove()` 清理。

此外：

- **父子关系**表示设备拓扑，例如 I²C 控制器下面连接传感器。
- **class（设备类）**按用途组织设备，例如输入设备、网络设备。
- **sysfs（`/sys`）**向用户空间展示这些对象及其关系。

**驱动模型负责管理和绑定；具体怎样操作硬件、怎样向应用提供接口，由驱动及所属子系统实现。**

从内核视角看，设备驱动体系是**一组内存中的对象、对象之间的关系，以及操作这些对象的函数**。

| 内容 | 内核中的表示 | 含义 |
|---|---|---|
| **设备实例** | `struct device` | “有一个具体设备”，记录父设备、总线、绑定的驱动等 |
| **驱动** | `struct device_driver` | “这套代码能管理哪些设备”，记录匹配信息、回调等 |
| **总线** | `struct bus_type` | 组织设备与驱动，通过 `match()` 等回调协调匹配和绑定 |
| **设备类** | `struct class` | 按用途组织设备，方便统一展示与访问 |
| **硬件描述** | 如设备树的 `struct device_node` | 提供地址、中断、`compatible` 等信息，供创建设备和初始化使用 |
| **驱动私有数据** | 驱动自行定义的结构体 | 保存某个设备实例的寄存器映射、锁、缓冲区等运行状态 |

具体总线会扩展通用对象。例如 I²C 中，`struct i2c_client` 内嵌 `struct device`，`struct i2c_driver` 内嵌 `struct device_driver`。

注册后，内核把对象加入对应的管理集合。总线尝试匹配设备和驱动，并通过相应总线的探测流程调用驱动的 `probe()`；成功后，设备的 `dev->driver` 指向该驱动，驱动通常还会把私有数据关联到设备。

因此要区分三个层次：

- **硬件或虚拟设备**：实际被操作的对象。
- **内核设备对象**：内核对它的记录。
- **驱动代码及驱动对象**：代码实现操作，驱动对象让内核能够管理、匹配和调用这套代码。

`/sys` 是这些内核对象的用户空间展示；`/dev` 中的设备节点则是某些设备向应用提供的访问入口，**并非每个 `struct device` 都对应一个 `/dev` 节点**。

主要有以下几类。**接口通常由设备所属子系统规定，驱动实现对应操作。**

| 接口 | 用户如何访问 | 典型用途 |
|---|---|---|
| **字符设备** | `/dev/xxx`，使用 `open/read/write/ioctl/poll/mmap` 等 | 串口、输入设备、GPIO、各种控制接口 |
| **块设备** | `/dev/sda`、`/dev/mmcblk0` 等，直接读写或挂载文件系统 | 磁盘、SD 卡 |
| **sysfs 属性** | 读取或写入 `/sys/...` 下的属性文件 | 查询状态、配置参数、查看设备关系 |
| **网络接口** | Socket，以及 Netlink 等控制接口 | 通过网卡收发数据、配置网络 |
| **子系统专用接口** | 使用该子系统规定的设备文件、操作和库 | ALSA 音频、V4L2 视频、IIO 传感器等 |

另外还有：

- **`/proc`**：主要展示系统与进程信息，也有部分控制接口。
- **debugfs**：主要用于驱动调试，通常不作为稳定的应用接口。

一个设备可以同时提供多个接口。例如传感器通过 **sysfs 配置采样参数，通过字符设备读取连续采样数据**。

注意，**`ioctl`、`poll`、`mmap` 是设备文件上的操作方式，并不是与字符设备并列的设备类型**。
